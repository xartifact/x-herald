# x-llm-gateway 开发路线图

**更新日期**: 2026-01-27
**开发模式**: 功能驱动的全栈同步开发
**原则**: 每个功能同时完成前后端，再进入下一个功能

---

## 🎯 开发策略

### 核心原则

- ✅ **全栈同步**: 每个功能都同时实现前端界面和后端 API
- ✅ **功能完整**: 一个功能的前后端都完成后，才开始下一个
- ✅ **快速迭代**: 每个功能都可以独立测试和使用
- ✅ **用户优先**: 优先实现用户可见的功能

### 为什么这样做？

| 传统方式 | 全栈同步方式 | 优势 |
|---------|------------|------|
| 先完成所有后端 API | 每个功能同时做前后端 | ✅ 更快看到成果 |
| 前后端分离开发 | 前后端紧密协作 | ✅ 减少返工 |
| 后期集成测试 | 边开发边测试 | ✅ 更早发现问题 |
| 延迟交付价值 | 快速交付价值 | ✅ 更好的反馈循环 |

## 🔄 开发流程

### 每个 Phase 的标准流程

1. **需求确认**
   - 明确前后端功能范围
   - 确定 API 接口设计
   - 确定 UI 交互设计

2. **后端开发**（如果未完成）
   - 实现 API 接口
   - 编写单元测试
   - 更新 API 文档

3. **前端开发**
   - 实现 UI 界面
   - 集成 API
   - 处理错误和边界情况

4. **集成测试**
   - 测试前后端协作
   - 测试完整的用户流程
   - 修复发现的问题

5. **用户测试**
   - 手动测试所有功能
   - 验证交互体验
   - 收集反馈

6. **文档更新**
   - 更新功能文档
   - 更新 API 文档
   - 记录设计决策

7. **代码审查**
   - 检查代码质量
   - 检查错误处理
   - 检查性能

8. **发布**
   - 合并到主分支
   - 更新 CHANGELOG
   - 部署到测试环境

## 📝 开发规范

### 代码风格

- TypeScript 严格模式
- ESLint + Prettier 格式化
- 语义化的变量和函数命名
- 充分的代码注释

### Git 提交规范

```
feat: 添加供应商管理界面
fix: 修复模型删除时的关联检查
docs: 更新 API 文档
style: 格式化代码
refactor: 重构路由选择逻辑
test: 添加单元测试
chore: 更新依赖
```

### API 设计规范

- RESTful 风格
- 统一的错误响应格式
- 分页参数统一（page, limit）
- 排序参数统一（order_by, order）

### 前端开发规范

- 组件化开发
- 使用 shadcn/ui 组件
- 统一的错误处理（Toast）
- 统一的加载状态（Skeleton）
- 表单使用 react-hook-form + zod

## 🎓 技术栈

- **Runtime**: Bun 1.3.6+

- **数据库**: PostgreSQL 16
- **ORM**: Drizzle ORM 0.29.3
- **认证**: JWT
- **日志**: Pino 8.17.2

- **框架**: Next.js 16.1.4 (App Router)

- **样式**: TailwindCSS 4.1.18
- **表单**: react-hook-form + zod
- **图标**: lucide-react
- **Toast**: sonner

### 开发工具

- **包管理**: Bun
- **Monorepo**: Bun workspaces
- **版本控制**: Git
- **容器化**: Docker + Docker Compose
